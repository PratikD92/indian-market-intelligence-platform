# ADR-017: Separate Authentication from Authorization and Enforce Pre-Retrieval Authorization

**Status:** Accepted

**Date:** 2026-09-09

## Context

The platform supports multiple user personas with different permissions and processes sensitive financial, ownership, and client-specific data. Authentication alone cannot prevent unauthorized access to restricted documents, GraphRAG relationships, or vector search results in a multi-tenant environment.

## Decision

Separate identity management from authorization and enforce authorization before data retrieval.

- **Auth Service** authenticates users through OIDC/OAuth, issues JWTs, and manages refresh tokens.
- **Policy / Guardrail Service** performs RBAC, tenant isolation, tool permissions, and compliance policy enforcement.
- Every protected request is authorized before accessing the Knowledge Store.
- The Policy / Guardrail Service passes authorization filters (`id`, `role`, `classification`, `scope` etc) to the Knowledge Store.
- PostgreSQL, pgvector, and GraphRAG apply these filters during retrieval, ensuring unauthorized data is never retrieved.

## Consequences

### Advantages

- Clear separation between authentication and authorization.
- Prevents unauthorized data leakage.
- Enforces consistent access control across RAG, GraphRAG, and MCP tool calls.
- Keeps security policies centralized in a single service.

### Trade-offs

- Adds an authorization step to protected requests.
- Requires consistent propagation of JWT claims between services.
- Authorization filters must remain synchronized with data metadata.

## Alternatives Considered

| Alternative | Reason Rejected |
|------------|-----------------|
| Auth Service performing both authentication and authorization | Rejected because it tightly couples identity management with business authorization policies, making RBAC, tenant isolation, compliance rules, and tool permissions harder to evolve independently. |
| Post-retrieval filtering | Rejected because unauthorized documents could still be retrieved before filtering, increasing the risk of data leakage. |
