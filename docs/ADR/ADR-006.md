# ADR-006: Adopt Google ADK for Multi-Agent Orchestration

**Status:** Accepted

**Date:** 2026-08-20

## Context

The platform executes complex financial research tasks that require planning, retrieval, financial analysis, compliance checks, industry research, and result synthesis. Managing these would require complex orchestration logic.

## Decision

Use **Google Agent Development Kit (ADK)** as the multi-agent framework.

- A single **Research / Agent Service** hosts the ADK runtime.
- A **Root Agent** plans execution and delegates work to specialized agents.
- Specialized agents execute **in-process**, avoiding unnecessary microservice boundaries.
- External tools are accessed through the **MCP / Tool Service**.

The ADK agent hierarchy includes:

- Root Agent
- Fetch Agent
- Financial Expert Agent
- Compliance Agent
- Industry Researcher Agent
- Consolidation Agent

## Consequences

### Advantages

- Simplifies multi-agent orchestration.
- Reduces inter-service network latency through in-process delegation.
- Keeps deployment and scaling straightforward.
- Allows specialized agents without creating additional microservices.

### Trade-offs

- Agents scale together as one service.
- Individual agents cannot be deployed independently.

## Alternatives Considered

| Alternative | Reason Rejected |
|------------|-----------------|
| Separate microservice per agent | Increased operational and networking complexity. |
| Custom orchestration framework | Higher implementation and maintenance effort. |
| Single LLM without specialized agents | Reduced task specialization and modularity. |
