# ADR-007: Keep All ADK Agents Within a Single Research/Agent Service

**Status:** Accepted

**Date:** 2026-08-20

## Context

The multi-agent workflow includes planning, retrieval, financial analysis, compliance checks, industry research, and result synthesis. Initially, each agent was considered as a separate microservice, but these agents execute as coordinated units within the same Google ADK runtime.

## Decision

Host all ADK agents within a single **Research / Agent Service**.

- The **Root Agent** orchestrates execution.
- Specialized agents communicate **in-process**.
- The service exposes a single gRPC interface to the **Research Orchestrator**.
- External capabilities remain isolated behind the **MCP / Tool Service**.

## Consequences

### Advantages

- Lower latency through in-process agent communication.
- Simpler deployment and scaling.
- Reduced operational overhead.
- Maintains clear logical separation without unnecessary microservices.

### Trade-offs

- All agents scale together.
- Individual agents cannot be deployed independently.
- Resource-intensive agents share the same runtime.

## Alternatives Considered

| Alternative | Reason Rejected |
|------------|-----------------|
| Separate microservice per agent | Increased network latency and operational complexity. |
| Independent deployment of each agent | Unnecessary for tightly coupled ADK execution. |
