# ADR-011: Use Valkey for Distributed Caching

**Status:** Accepted

**Date:** 2026-08-22

## Context

The platform serves repeated research queries and frequently accessed knowledge that should not require repeated retrieval, embedding lookups, or AI inference. A distributed cache is needed to reduce latency, lower infrastructure cost, and support horizontally scaled microservices.

## Decision

Use **Valkey** as the distributed caching layer.

- Cache frequently requested research responses.
- Cache retrieval results where appropriate.
- Invalidate affected cache entries after successful knowledge synchronization.
- Share cache across all application instances.

## Consequences

### Advantages

- Reduces response latency.
- Lowers AI inference and retrieval costs.
- Supports horizontally scaled microservices.
- Provides centralized cache management.

### Trade-offs

- Requires cache invalidation logic.

## Alternatives Considered

| Alternative | Reason Rejected |
|------------|-----------------|
| **Memorystore for Redis** | Rejected to avoid managed service lock-in, reduce infrastructure cost, and use the open-source Valkey ecosystem while retaining Redis compatibility. |
