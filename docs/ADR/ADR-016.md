# ADR-016: Benchmark the Platform Using Simulated Traffic up to 1M MAU

**Status:** Accepted

**Date:** 2026-08-24

## Context

The platform is designed to demonstrate production-grade scalability on GCP. Claims of supporting high user volumes should be backed by measurable evidence rather than theoretical architecture. Benchmarking must exercise the same production path used by real users while producing reproducible verification artifacts.

## Decision

Validate the deployed platform using simulated traffic ranging from **10K to 1M MAU**.

- Execute benchmarks against the **API Gateway** using HTTPS.
- Scale traffic gradually through predefined benchmark profiles.
- Allow GKE autoscaling and Cloud Service Mesh to operate under production-like conditions.
- Collect infrastructure and AI telemetry throughout the benchmark.
- Generate verification artifacts for reproducibility and replay.

## Verification Artifacts

- Throughput (requests/sec)
- Latency (P50, P95, P99)
- Error rate
- Autoscaling timeline
- CPU and memory utilization
- Distributed trace summary
- Infrastructure and AI cost summary
- Five-minute benchmark replay

## Consequences

### Advantages

- Produces measurable evidence of platform scalability.
- Validates autoscaling and resilience under realistic traffic.
- Demonstrates production readiness using reproducible results.
- Provides portfolio-ready benchmark artifacts.

### Trade-offs

- Benchmark execution incurs infrastructure and inference costs.
- Large-scale tests require careful resource planning.
- Results depend on the deployed environment and workload profile.

## Alternatives Considered

| Alternative | Reason Rejected |
|------------|-----------------|
| Synthetic architecture claims without benchmark execution | Rejected because scalability should be demonstrated through measurable, reproducible evidence rather than theoretical design alone. |
