# ADR-003: Use Cloud Service Mesh (Istio-based)

**Status:** Accepted

**Date:** 2026-08-19

## Context

The platform consists of multiple microservices communicating over gRPC. Implementing security, traffic management, retries, and telemetry within each service would increase application complexity and duplicate networking logic.

## Decision

Use **Cloud Service Mesh (Istio-based)** on GKE for all internal service-to-service communication.

- Envoy sidecar for each application microservice.
- Mutual TLS (mTLS) for secure communication.
- Centralized traffic management and retry policies.
- Integrated telemetry for observability.

## Consequences

### Advantages

- Removes networking concerns from application code.
- Provides secure service-to-service communication.
- Simplifies traffic management and resilience.
- Improves distributed tracing and observability.

### Trade-offs

- Additional infrastructure complexity.
- Sidecar resource overhead.
- Learning curve for Istio configuration.

## Alternatives Considered

| Alternative | Reason Rejected |
|------------|-----------------|
| Application-level networking | Duplicates retries, security, and telemetry across services. |
