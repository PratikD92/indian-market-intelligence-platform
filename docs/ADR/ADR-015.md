# ADR-015: Adopt a Layered AI Evaluation & Observability Pipeline

**Status:** Accepted

**Date:** 2026-08-23

## Context

The platform includes RAG, GraphRAG, and multi-agent workflows that require continuous quality assurance beyond infrastructure monitoring. The AI lifecycle must cover experiment tracking, retrieval quality, agent behavior, security testing, production AI observability, and inference cost monitoring.

## Decision

Adopt a layered AI evaluation and observability pipeline, with each tool responsible for a distinct stage.

| Stage | Tool | Responsibility |
|-------|------|----------------|
| Experiment Tracking | MLflow | Track prompt/model versions, evaluation runs, and compare experiments. |
| RAG Evaluation | Ragas | Evaluate retrieval and generation quality (recall, precision, faithfulness, relevance). |
| Agent Evaluation | DeepEval | Evaluate task success, planning, tool usage, and workflow correctness. |
| Security Evaluation | Promptfoo | Run red-team tests for prompt injection, jailbreaks, and data leakage. |
| AI Observability | Arize Phoenix | Capture LLM traces, prompt analytics, token usage, inference cost, latency, drift, datasets, and production AI behavior. |

The evaluation pipeline aligns with CI/CD:

- **Pre-release:** MLflow → Ragas → DeepEval → Promptfoo.
- **Production:** Arize Phoenix continuously monitors deployed AI workloads.

## Consequences

### Advantages

- Covers the complete AI lifecycle from development to production.
- Prevents quality regressions before deployment.
- Detects security vulnerabilities through automated red-team testing.
- Provides production visibility into prompts, agents, RAG retrieval, latency, token usage, and inference costs.
- Keeps each tool focused on a single responsibility.

### Trade-offs

- Additional CI/CD execution time.
- Requires curated evaluation datasets and security test suites.
- Multiple tools increase operational complexity.

## Alternatives Considered

| Alternative | Reason Rejected |
|------------|-----------------|
| Langfuse | Rejected because Arize Phoenix provides broader production AI observability, including integrated RAG debugging, agent tracing, dataset-driven evaluation, drift monitoring, prompt analytics, and inference cost visibility, allowing the platform to consolidate AI observability into a single tool without maintaining overlapping capabilities. |
