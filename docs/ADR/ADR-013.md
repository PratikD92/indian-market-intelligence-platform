# ADR-013: Use Rule-Based Metadata Generation and Content-Type-Driven Chunking

**Status:** Accepted

**Date:** 2026-08-22

## Context

The platform ingests multiple document formats, including PDFs, HTML pages, CSV files, Excel spreadsheets, JSON responses, filings, transcripts, and announcements. Applying a single chunking strategy to all content would reduce retrieval quality because different document types have different natural boundaries.

## Decision


Generate metadata using an LLM during **Market Data Ingestion** and use it to drive deterministic chunking during **Knowledge Synchronization**.

- Market Data Service detects document type and generates metadata such as `content_type`, `source`, `company_id`, and `document_id`.
- Knowledge Sync Service selects the chunking strategy using metadata instead of an LLM.
- Chunking remains deterministic and content-specific.

| Content Type | Chunking Strategy |
|--------------|-------------------|
| Annual Report | Parent-Child |
| Company Page | Section-based |
| Financial CSV | One row = one chunk |
| Financial Excel | One row = one chunk |
| API JSON | One object = one chunk |
| Press Release | Paragraph + overlap |
| Earnings Transcript | Speaker-turn |
| SEBI Filing | Section-based |
| Corporate Announcement | One announcement = one chunk |
| Director/Ownership Record | One relationship = one chunk |
| Industry Metrics | One metric record = one chunk |

## Consequences

### Advantages

- Consistent and reproducible chunking.
- Lower inference cost by avoiding LLM-based routing.
- Better retrieval quality across heterogeneous content.
- Clear separation between metadata generation and semantic enrichment.

### Trade-offs

- New document types require additional chunking rules.
- Rule maintenance becomes part of the ingestion pipeline.

## Alternatives Considered

| Alternative | Reason Rejected |
|------------|-----------------|
| Fixed chunk size with overlap for all content | Rejected because a one-size-fits-all approach reduces retrieval quality across heterogeneous data formats. Content-type-driven chunking preserves the natural structure of the content while remaining deterministic. |
