# ADR-002: Use Google Kubernetes Engine (GKE)

**Status:** Accepted

**Date:** 2026-08-18

## Context

The platform targets a production-grade deployment capable of scaling to **1M MAU** while running multiple microservices, long-running workflows, service mesh, observability, and benchmark workloads. The compute platform must support container orchestration, autoscaling, rolling deployments, and production networking.

## Decision

Deploy all application microservices on **Google Kubernetes Engine (GKE)**.

- Kubernetes as the orchestration platform.
- Horizontal Pod Autoscaler for service-level scaling.
- Rolling deployments for zero-downtime releases.
- Cloud Service Mesh (Istio-based) for service networking.
- Native integration with Google Cloud services, if using them (Pub/Sub, Cloud SQL, Monitoring).

## Consequences

### Advantages

- Production-grade container orchestration.
- Independent scaling of microservices.
- High availability and rolling updates.
- Native integration with the GCP ecosystem.

### Trade-offs

- Higher operational complexity than serverless.
- Kubernetes cluster management overhead.
- Additional infrastructure configuration.

## Alternatives Considered

| Alternative | Reason Rejected |
|------------|-----------------|
| Cloud Run | Less suitable for demonstrating service mesh and complex inter-service architecture. |
| Compute Engine | Manual scaling and orchestration overhead. |
| Self-managed Kubernetes | Unnecessary operational burden compared to managed GKE. |
