# ADR-019: Use Managed LLM API Instead of Self-Hosted LLM

**Status:** Accepted

**Date:** 2026-09-10

## Context

The platform must demonstrate production-grade scalability while supporting a benchmark of **80,000 concurrent users**, **4,000 RPS**, and **780,000 requests in a five-minute demonstration**.

Benchmark assumptions:

| Metric | Value |
|--------|------:|
| Demo Duration | 5 minutes |
| Requests | 780,000 |
| Peak RPS | 4,000 |
| Avg Input Tokens | 500 |
| Avg Output Tokens | 100 |
| Peak Output Token Generation | 400,000 tokens/sec |

Two deployment strategies were evaluated:

- **Managed API:** OpenAI GPT-5 Nano
- **Self-hosted:** Llama 3.1 8B on NVIDIA H100 GPUs using vLLM

## Decision

Use **OpenAI GPT-5 Nano (Managed API)** as the inference backend.

The platform delegates model hosting, scaling, KV cache management, and inference optimization to the managed API while retaining ownership of orchestration, retrieval, evaluation, and observability.

## Cost Analysis

### Managed API

| Metric | Value |
|--------|------:|
| Input Cost (1M tokens) | $0.05 |
| Output Cost (1M tokens) | $0.40 |
| Estimated Benchmark Cost | **$50.70** |

### Self-hosted

| Metric | Value |
|--------|------:|
| Model | Llama 3.1 8B |
| H100 Throughput | 2,750 tokens/sec |
| Required Throughput | 400,000 tokens/sec |
| H100 GPUs Required | 146 |
| GKE Instances (a3-highgpu-4g) | 37 |
| Estimated Provisioning Time (incl. warm-up, loading model, deleting cluster) | ~10 minutes |
| Estimated Benchmark Cost | **~$284.09** |

## Comparison

| Metric | Managed API | Self-hosted |
|--------|-------------:|------------:|
| Cost | **$50.70** | ~$284 |
| GPUs Required | 0 | 148 H100 |
| Kubernetes GPU Management | No | Yes |
| KV Cache Management | Managed | vLLM |
| Warm-up Required | No | Yes |

## Consequences

### Advantages

- Approximately **5.6× lower benchmark cost**.
- No GPU provisioning or model warm-up.
- Automatic scaling and managed inference infrastructure.
- Eliminates operational overhead for KV cache and model serving.

### Trade-offs

- Vendor dependency on OpenAI APIs.
- Less control over model hosting compared to self-hosting.
- API availability becomes an external dependency.

## Alternatives Considered

| Alternative | Reason Rejected |
|------------|-----------------|
| Self-hosted Llama 3.1 8B on GKE | Rejected due to significantly higher infrastructure cost, GPU provisioning overhead, model warm-up time, and operational complexity without providing sufficient benefit for the benchmark objectives. |
